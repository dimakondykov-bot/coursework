# План работы и TODO-лист (для ассистента)

Файл содержит пошаговый план, декомпозицию задач и конкретный TODO-лист для реализации сервисов в проекте `financial_assistant`.

## Цель

Реализовать набор сервисов в `src/services.py`, покрыть их тестами, подключить логирование и обеспечить простую интеграцию через `main.py`.

## Краткий план (высокоуровневый)

1. Подготовка: изучить формат входных данных (`data/operations.xlsx`) и существующие утилиты в `src/utils.py`.
2. Реализация сервисов в `src/services.py`:
   - `analyze_profitable_cashback_categories` — анализ выгодности категорий кешбэка.
   - `investment_bank` — расчет суммы отложений через округление (шаг 10/50/100).
   - `simple_search` — простой поиск по описанию/категории.
   - `search_phone_numbers` — поиск транзакций с мобильными номерами.
   - `search_person_transfers` — поиск переводов физлицам.
3. Покрытие тестами (`tests/test_services.py`) — для каждого сервиса минимум по 2 теста (happy path + edge case).
4. Интеграция: примеры вызова в `main.py`, логирование, документация (docstrings + README дополнение).
5. Quality gates: запуск pytest, проверка линтинга/типов (если есть). Исправления по результатам тестов.

## Acceptance criteria (критерии приемки)

- Все реализованные функции имеют docstring и аннотации типов.
- Для каждой реализованной функции есть как минимум один unit-тест (pytest). Все тесты проходят.
- Логирование присутствует и покрывает ключевые шаги и ошибки.
- Функции корректно обрабатывают пустые/неправильные входные данные (не падают без понятной ошибки).

## Edge cases и проверки

- Даты в нестандартных форматах — логировать и пропускать/нормализовывать.
- Суммы в строковом виде — попытаться привести к float, иначе логировать и пропускать.
- Нулевые и положительные суммы для расходных/доходных операций — учитывать знак при расчетах для `investment_bank`.
